# Centring the v4 leave-wells-out predictions

Each ensemble is rebuilt exactly as `src.models.regimes.assemble_lwo`, including its seed check and the response model's sd floor, and checked against the frozen `predictions.parquet`. The before scores come from each frozen run's own `metrics_per_well.csv`.

Rebuilt prediction keys must match exactly and prediction values must match within 1e-12 m absolute tolerance (floating-point aggregation order). Differences in prediction means and seed spread are recorded separately in `summary.csv`. LightGBM's own assembler (`src/models/lgbm.py`) uses numpy's population sd; `assemble_lwo` uses pandas' sample sd. This diagnostic keeps `assemble_lwo`'s spread. Seed spread does not enter any score or the centring correction.

For well i, W contains its non-missing observed heads in the training split (2005-01-01 to 2019-12-31). These are exactly the rows used by `build_panel` for mu and sd (pandas mean and sample sd). No extra quality-share or placeholder mask enters those statistics. Head availability selects W; no head magnitude beyond the permitted mu is used. Every W week must have a prediction, otherwise the run is skipped with a reason. The correction is `pred_c = pred - mean_W(pred) + mu`. It only translates each series: its temporal shape and seed spread stay the same.

The after scores use `src.models.evaluate.score` and `summarise`, with the same splits, variants, placeholder masks, benchmarks and minimum 26-week support. Exact scored-week support is checked against the frozen metrics. Table endpoints use core wells, simulation, horizon 0, variant `all`. Median absolute offsets also use core wells; the CSV includes an all-well median. Offsets for every predicted well and their W sizes are saved in each diagnostic run's `offsets.csv`.
